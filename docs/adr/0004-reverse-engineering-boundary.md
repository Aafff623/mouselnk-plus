# ADR-0004: 放宽逆向边界——允许反编译用于理解机制，仍禁止复制

- Status: accepted
- Date: 2026-10-10

## Context

项目从建立之初就有一条明确的来源边界（原 `AGENTS.md`）：「**不得包含、反编译、反汇编或逐字节复制** MouseInc / Aitiy 的代码、资源或产物」。这条规则的由来是作者本人的要求——不便提供源码，请从零独立实现，并使用自己的软件名称、图标、界面和服务地址。因此本机两个程序一直只作**行为参照（黑盒 oracle）**：允许运行观察交互、读取它们释放到磁盘的 JSON 配置、比对功能清单，但不允许从中提取实现代码。

实践中这条边界带来一个持续的成本：**两个程序的核心逻辑（钩子调度、手势引擎、动作执行、截图/贴图/画中画、OCR 调度）只存在于 exe 里**，黑盒观察能确认「行为是什么」，却无法回答「为什么这样设计、边界条件如何处理、某个坑他们怎么绕的」。阶段 1 的实现已经多次遇到这类问题（例如钩子存活判定、右键补发与拖动的配对、超时语义），只能靠规格与社区线索反推。

2026-10-10，owner 明确授权放宽这条边界：**允许反编译/反汇编用于理解实现机制**。同时确认原有两条约束不变：① 不得逐字节复制代码、资源或产物；② 交付物必须是独立实现，并使用自有的名称、图标、界面与服务地址。本仓库是**公开仓库**，因此反编译产物本身也不得入库。

## Decision

1. **允许**对 `MouseInc.exe` / `Aitiy.exe` 做**反编译、反汇编与静态分析**，用于理解实现机制、设计取舍与边界处理。工具链使用 REA（`rea-agents`，MCP 工作区级常驻；原生分析引擎为 Ghidra）。
2. **仍然禁止**：逐字节复制代码、资源或产物；把反编译产物（伪代码、反汇编清单）直接搬进本工程。交付物必须是独立实现。
3. **仍然禁止**照搬品牌与具体设计：参考程序的图标、字体、界面文案、品牌名、服务域名的具体设计不得复制，也不得从其文件里提取资源（沿用原规则，理由见 `docs/icon-spec.md`）。
4. **反编译产物一律放 `temp/`，不入 Git**（仓库公开）。分析报告可以沉淀为 `CONTEXT.md` 里的事实，但必须写成**结论**而非代码搬运。
5. 本决策同步落进 `AGENTS.md`（边界条款）、`README.md`（对外说明）与 `CONTEXT.md`（硬约束第 1 条）。

## Consequences

- 更容易：核心机制的疑问现在可以直接取证回答，而不是靠行为反推；`CONTEXT.md` 里标注为【推断】的条目（如静态链接的 ONNX Runtime、动作族的内部调度）有机会升级为【实测】。
- 更容易：MouseInc 的设置界面是随包发布的 Vue/webpack bundle，属于**已发布的可读 JS 产物**，静态分析不需要反编译引擎即可拿到完整字段集与通信协议。
- 更困难 / 新增义务：本工程现在需要**自己守住「理解但不复制」这条线**。反编译产物是本地材料，任何进入 `src/` 的东西都必须是独立实现；代码评审与提交信息里要能看出这一点。
- 新增义务：本机需要安装 Ghidra（+ 匹配的 JDK）才能启用原生分析；该引擎**不进本工程、不进发行物、不登记 `THIRD-PARTY-NOTICES.md`**（它只是本机分析工具，不是交付依赖）。
- 风险：公开仓库中「我们反编译了参考程序」这一事实本身会被看到。这是 owner 在知情下接受的取舍，边界以「不复制、不冒充」为限。

## Alternatives considered

**维持原边界（只做黑盒分析）**：法律与观感上最保守，且与项目早期的对外表述一致。否决原因：owner 判断理解机制的收益大于保守成本，且「行为复刻、代码独立」的目标不因「看过实现」而改变——真正的红线是**复制**，而不是**理解**。

**只做 REA 的无引擎能力（JS bundle / 配置 / 运行时抓取）**：零安装成本，且能拿到设置界面的完整字段集与协议。否决原因：这只覆盖 MouseInc 的设置界面，**完全覆盖不到 Aitiy（纯原生、无 JS 资源）**，也覆盖不到两个 exe 的核心逻辑——而那正是最需要理解的部分。作为第一步仍然有价值，故保留为分析的起点。

**换成 IDA / Hopper**：IDA 是商业授权，Hopper 仅 macOS。否决原因：本机是 Windows，Ghidra 是唯一免费且跨平台可用的原生分析引擎。
