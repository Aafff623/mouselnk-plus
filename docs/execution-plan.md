# mouselnk-plus 执行计划

本文件是**执行总纲**：工作原则、技术选型结论、标准流程、阶段任务地图、验证矩阵与风险登记。

- `TODO.md` 是**任务状态板**（做什么、做到哪）；本文件是**流程与选型依据**（怎么做、为什么这么做）。
- 两者的分工：本文件不记录进度，`TODO.md` 不重复理由。
- owner 说「按计划全做完」时，执行顺序与门禁以本文件为准。

---

## 1. 工作原则（不可违背）

1. **不造轮子。** 任何**通用功能**（推送更新、HTTP、加密哈希、压缩、OCR、崩溃上报、日志、测试框架、图标…）先查现成方案，且**必须覆盖「Windows 系统自带 API」这一档**；对比 2–3 个候选后用**表格**呈现，**先同步 owner 并得到确认再集成**。只有社区确实没有合适方案时才自己实现，且必须先说明「为什么没有轮子可用」。详见 `AGENTS.md` 的「依赖与技术选型纪律」。
2. **系统自带优先。** Windows 自带能力 = 零体积、零依赖、零许可证义务，是最省的轮子。
3. **轻量是过滤器，不是否决权。** 体积/内存/线程/依赖 DLL 数是选型约束；若只有重量级方案可用，把取舍摆给 owner 决定，不默默自研更差的替代品。
4. **步骤化交付。** 每完成一个任务：编译通过 → 真机验证 → 更新文档 → **Git 提交** → 推送。阶段收尾要有可运行产物。
5. **行为复刻、代码独立。** 不反编译参考程序；参考程序只作行为对照。文本/图标/界面/服务地址全部自建。
6. **证据分级。** 每条结论标注 `【实测】` / `【来源】` / `【推断】` / `【未找到】`。未实测的推断不得写成结论。

### 2.2 待确认（调研已完成，等 owner 拍板）

| 领域 | 作者规格点名 | 调研结论 | 关键依据 |
|---|---|---|---|
| **哈希与摘要** | LibTomCrypt + LibTomMath | **改用 Windows BCrypt/CNG**（系统自带） | BCrypt 覆盖 MD5/SHA-1/SHA-256（Vista+），**0 字节增量、0 许可证登记**；LibTomMath 本项目根本不需要（官方 README 称 MPI 仅在构建 binaries 时需要）。签名验证用 CNG 验签或 `WinVerifyTrust` |
| **HTTP** | WinINet | **保留 WinINet 即可**（追求更轻可换 WinHTTP，但代理行为需注意） | 两者都是系统自带，第三方只剩 libcurl——官自述静态构建「not for the faint of heart」且警告勿混用 CRT，排除。若换 WinHTTP 需在 CONTEXT 记为偏离规格 |
| **ZIP 解压** | miniz | **保留 miniz**（不可替代） | Windows 的 Compression API 只有 MSZIP/XPRESS/LZMS **没有 DEFLATE**，解不了 .zip；ntdll 的 raw DEFLATE 仅 Win11 24H2+ 且未公开。**可选组件包格式若改由我方定义（MSZIP/LZMS），则可完全不用 miniz** |
| **OCR** | 「可部署的本地引擎或自有服务」 | **主用 Windows 系统 OCR（`Windows.Media.Ocr`），高质量需求走按需下载的可选组件（PP-OCRv6 tiny，独立进程）** | 系统 OCR **主程序 0 字节增量**（语言数据在系统侧，本机实测 zh-cn 为 2.3 MB），本机实测可识别、1000×140 图 31 ms；ONNX Runtime + PP-OCR 约 24 MB 且是 Aitiy 130–176 MB 空闲内存的来源；Tesseract 中文质量口碑差且 chi_sim 数据 2.47–44 MB |
| **自动更新** | 「自有服务、签名密钥、发布包」 | **无合适轮子 → 自研最小更新器** | 唯一原生候选 WinSparkle 单 DLL 就 2.2–2.8 MB（大于 MouseInc 整包）且破坏单文件；Velopack/Squirrel/Omaha 都以「安装器 + 目录布局」为前提，与单文件 portable **架构互斥**；Squirrel 已停滞、Omaha 已归档 |
| **崩溃上报** | 「更新机制」同阶段 | **无合适轮子 → 用系统 dbghelp `MiniDumpWriteDump` + 本地环形日志 + 手动导出诊断包** | Crashpad 必须随包另一个 handler 子进程且构建不走 CMake；sentry-native 默认指向云端且仍要额外进程；WER LocalDumps 需管理员写 HKLM，便携场景不可用 |
| **日志库** | 要求「Logging：错误和诊断信息」 | **自研最小日志**（不进 spdlog） | 轮转上限与诊断包导出本就要自己写；句柄数/私有提交/线程数快照是纯 Win32；spdlog 只省「写文件+按大小轮转」却带来 fmt 翻译单元与必须 CI 量化的体积 |
| **单元测试** | 规格 §17 要求自动化测试 | **doctest** | CMake/CTest 原生（`add_test`）、单头文件、模板最轻；GoogleTest 需编译成库、Catch2 非单头；**MS 自带 CppUnitTestFramework 需要 VS Native Test 项目 + vstest，Ninja 下不适用**。测试 exe 不进发行物，故与 /MT 约束无关 |
| **设置界面前端栈** | 本地 HTML/CSS/JS | **原生 HTML/CSS/JS（零构建）** | 界面是表单+列表+颜色/热键录入，不需要响应式框架；零 Node/npm、零体积税、产物可直接提交仓库。Vue 3 + Vite 作备选（MouseInc 路线，但需整套 npm 链） |
| **图标** | — | **设置界面用 Phosphor（按需挑 SVG，MIT，本机已装）；原生/托盘用 Segoe Fluent Icons（系统自带）** | Phosphor 60 个图标约 21 KB；Segoe 字体零体积但**不得随包分发**，且 Win10 会回落到 Segoe MDL2 |
| **本地 HTTP 服务** | 「如采用本地 HTTP/WebSocket 则用 Mongoose」 | **不需要 Mongoose** | WebView2 官方提供 `SetVirtualHostNameToFolderMapping`，把本地 `ui/` 目录映射为虚拟域名即可离线加载，比自建回环服务少一个监听端口和一个依赖 |

## 3. 标准工作流

### 3.1 引入通用功能 / 依赖（5 步，必须先确认）

1. **查轮子**：用搜索工具查当前技术栈（C++20 / MSVC / Win32 / 单文件 portable）下的主流方案，**必须包含「Windows 自带 API」这一档**。
2. **表格对比 2–3 个候选**：维护活跃度（最近发布/提交、issue 响应）、社区采用度、许可证、**体积与内存增量**、能否静态链接、是否 header-only、与本工程约束的匹配度。
3. **同步 owner**：给出推荐与理由，**等待确认**。不先斩后奏。
4. **集成**：遵循现有依赖与技术栈，不重复引入功能重叠的库。
5. **登记**：写入 `THIRD-PARTY-NOTICES.md`，记录来源、版本、许可证、**体积与内存增量的实测数字**（不写「很小」）。

**只有第 1 步证明「没有轮子」时才自研**，并在计划或提交信息里写明为什么。

### 3.2 实现一个任务（7 步）

1. 读 `CONTEXT.md` 的「硬约束」与「已知失效模式」——相关坑先看一遍。
2. 确认本任务需要的轮子已按 3.1 确认过（否则先走 3.1）。
3. 实现：遵循作者规格的模块划分；资源一律 RAII；不引入未确认的依赖。
4. 静态检查：编译零警告（`/W4`），参数校验与边界分支写全。
5. **自动化验证**：能自动化的必须自动化（见第 5 节验证矩阵）；写脚本放 `temp/scripts/`（不入库）。
6. **真机验证**：涉及钩子/托盘/多屏/DPI/权限的，必须在真实桌面验证；无法自动化的部分明确写出来交 owner 点验。
7. 更新 `CONTEXT.md` / `TODO.md` / `README.md`（按需）→ **Git 提交** → 推送。

### 3.3 提交与推送规范

- **粒度**：一个任务一个提交；纯文档调整单独提交。
- **消息**：`<type>(<scope>): <简述>` + 正文说明「做了什么、为什么、验证到什么程度」。type 用 `feat` / `fix` / `docs` / `chore` / `test`。
- **推送**：本地提交后直接推 `origin main`（仓库是公开的，推送即发布）。
- **绝不提交**：`temp/` 载荷、作者需求原文、调研报告、本机路径、凭据、任何个人信息。

### 3.4 阶段收尾（门禁）

每个阶段结束必须满足：

1. 工程可编译、程序可运行（作者规格「十六、分阶段实现」的硬要求）。
2. `README.md` 的「当前状态」已更新。
3. 已完成任务从 `TODO.md` 移除；新增的待确认项写入 `CONTEXT.md`。
4. 真机验证记录（截图或日志路径）写进提交信息或 `temp/reports/`。
5. 推送完成。

### 阶段 2 — 设置界面、录制与规则

关键任务：T-0010 模板录制、T-0011 原生简单设置窗口、T-0012 WebView2 设置界面、T-0013 应用规则、T-0014 排除与全屏、T-0015 全局热键、T-0016 变量展开与选中文字、T-0017 配置迁移。

**本阶段的硬约束**：

- WebView2 必须**打开才创建、关闭即销毁**，绝不把常驻功能放进它（官方《Performance best practices》承认多进程开销）。
- WebView2 的 `userDataFolder` 必须**显式指定**：便携模式用 exe 同目录（先探测可写性），回落 `%LOCALAPPDATA%`。注意 `WEBVIEW2_USER_DATA_FOLDER` 环境变量与注册表策略会**覆盖**程序传入的值。
- 静态 loader（`WebView2LoaderStatic.lib`）是保住单文件的关键；**静态 CRT `/MT` 与它的兼容性无官方说明，必须在 T-0012 用真实构建验证**。
- 用 `SetVirtualHostNameToFolderMapping` 加载本地 `ui/`，**不引入 Mongoose、不起回环服务**。

### 阶段 3 — 鼠标扩展与文本菜单

T-0018 右键滚轮、T-0019 边缘滚轮、T-0020 热角、T-0021 Alt 系列与滚轮扩展、T-0022 文本操作菜单。

**硬约束**：必须制定**明确的事件优先级**，保证每个输入最多被一个功能消费；左右键与中键的按下/抬起必须配对处理。

### 阶段 4 — 截图、贴图、画中画与文本工具

T-0023 截图、T-0024 贴图、T-0025 画中画、T-0026 OCR、T-0027 文本转换与二维码、T-0028 音量与亮度。

**本阶段的硬约束**：

- OCR：**系统 OCR 为主路径**（`Windows.Media.Ocr`，C++/WinRT 头文件 + 链接 `windowsapp.lib`）。MS 文档把 `OcrEngine` 列入「需要 package identity」清单，但本机以普通进程实测可用——因此按「**探测可用则用、否则降级**」实现，并在文档里写明这是文档层面「不受支持」的用法。CJK 结果需去多余空格；`AvailableRecognizerLanguages` 为空时引导用户安装系统语言包。
- OCR 高质量路径：可选组件包（`ocr-helper.exe` + PP-OCRv6 tiny onnx + 字典），**独立进程、按需下载、配置内固定 SHA-256 校验、空闲退出**。
- 截图/贴图/画中画的位图缓冲区必须**有上限与明确释放时机**（一张 3840×2160×32bit 就是约 33 MB）。
- 哈希摘要用 BCrypt（不引入 LibTomCrypt）。

### 阶段 5 — 可选增强与发布

T-0029 按键回显/提示/音效、T-0030 目录跳转、T-0031 更新机制、T-0032 长稳验收。

**更新机制（自研，无轮子）**：WinHTTP 拉清单 → Ed25519/证书验签 → 下载到临时目录 → 校验 → 自替换（运行中的 exe 先重命名 `.old`，写入新版，重启后清理）。**自替换流程必须实测**。默认关闭联网。
**崩溃诊断**：dbghelp `MiniDumpWriteDump`（延迟加载）+ 本地环形日志 + 用户可手动导出诊断包。**前提是每次发布归档 PDB**，否则 dump 无意义。
**发布**：附发布包 + 签名 + 校验值，绝不依赖参考程序的更新地址。

## 6. 风险登记

| 风险 | 影响 | 对应任务 | 验证方式 |
|---|---|---|---|
| 低级钩子被系统静默移除（回调超 300ms） | 手势莫名失效 | T-0004（装钩线程 + 回调零分配）、T-0033（看门狗） | 真机划动 + 看门狗日志区分两种静默 |
